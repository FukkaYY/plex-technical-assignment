# テスト方針

2週間のため網羅率の数値目標は置かず、権限境界と必須ユーザーフローを優先する。

## Rails model

- メールアドレスの正規化と一意性
- roleの許容値
- プロフィール項目の検証
- 関連と削除方針
- パスワード認証
- 会話参加者と送信者の整合性

## Rails request

- 学生登録
- ログイン、ログアウト、`GET /me`
- 学生一覧・詳細
- メッセージ送信・会話取得
- 401、403、404、422
- レスポンスに非公開項目が含まれないこと

## Next.js unit/component

- 登録・ログインフォームの入力とエラー
- 学生カード、詳細表示
- 読み込み・空・エラー状態
- ページネーション
- メッセージ入力の文字数表示と送信状態

## E2E

1. 学生登録からマイページ表示
2. 企業ログインから学生一覧・詳細
3. 企業からメッセージ送信
4. 学生が受信内容を確認
5. 異なるロール・他ユーザーのリソースへアクセスできないこと

PlaywrightのChromiumで1〜4を連続した必須フローとして実行し、学生セッションで企業画面を開けないことも確認する。Docker ComposeでアプリとDBを起動し、seedのデモ企業・デモ学生を利用する。GitHub Actionsでは通常のfrontend・backendジョブと分離し、失敗時にHTMLレポート、スクリーンショット、動画、trace、コンテナログをartifactとして7日間保存する。
