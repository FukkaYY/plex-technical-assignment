# 認可

## ロール

- `student`: 自身のプロフィールと受信会話へアクセスする。
- `company`: 学生一覧・詳細と、自社の会話へアクセスする。

## 原則

- 画面制御だけでなくRails側で必ず認可する。
- クライアントから渡されたroleを信用しない。
- 所有者・参加者の判定はログイン中ユーザーから行う。
- 企業向け学生別メッセージAPIは、ログイン中企業と対象学生の会話だけを取得・更新し、他社の会話を返さない。

## 企業認可の共通処理

- 企業専用APIは共通の企業認可処理を使用する。
- 未ログインは `401 Unauthorized` と `base` / `unauthenticated` を返す。
- 学生ロールは `403 Forbidden` と `base` / `forbidden` を返す。
- フロントエンドの画面制御は利便性のために行い、API側の認可に代用しない。

## アクセス表

| リソース | 未ログイン | student | company |
|---|---:|---:|---:|
| 学生登録 | 可 | 不要 | 不要 |
| `GET /me` | 401 | 可 | 可 |
| 学生一覧・詳細 | 401 | 403 | 可 |
| 企業からの送信 | 401 | 403 | 可 |
| 学生の受信会話 | 401 | 本人のみ | 自社参加分のみ |

## 情報公開

- 企業向け学生APIにメールアドレスを含めない。
- 学生向け企業情報は企業名を最低限とし、追加項目は別途決定する。
- 存在を隠す必要があるリソースでは403と404の使い分けを検討する。
