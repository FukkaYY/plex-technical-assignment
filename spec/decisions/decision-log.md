| D-009 | Railsの `cookie_store` とHttpOnly Cookieで認証する。 | ブラウザJavaScriptから認証情報を読めない構成にし、MVPでサーバー側セッションストアを追加しないため。 | 採用 |
| D-010 | HTMLは公開概要、分割Markdownは実装仕様の正本とする。 | 人間向け閲覧性とAI・実装時の参照効率を両立するため。 | 採用 |
| D-011 | 公開意図が確認できない課題URLをリポジトリへ掲載しない。 | 限定公開情報の拡散リスクを避けるため。 | 採用 |
| D-012 | P0はNext.jsからRailsへの同一オリジン転送とCSRFトークンヘッダーを使用する。 | Cookie認証のCSRFリスクを抑え、フロントのAPI接続先を同一オリジンに統一するため。 | 採用 |
| D-013 | 学生登録後の学生マイページは登録者名、登録成功状態、ログアウト導線を最小要件とする。 | 学生登録の完了を画面上で検証でき、受信機能と分離して実装できるため。 | 採用 |
| D-014 | `POST /api/v1/session` を学生・企業共通とし、指定roleと保存済みroleの一致を検証する。 | 認証処理を共通化しつつ、企業ログイン画面から学生セッションが作成されることを防ぐため。 | 採用 |
| D-015 | 共通ログインAPIにIP単位の試行制限を設ける。 | デモ環境でも資格情報への総当たりを抑制するため。 | 採用 |
| D-016 | 学生一覧・詳細・メッセージ送信の学生IDに `users.id` を使用する。 | 学生を表すIDを機能間で統一し、関連解決を単純にするため。 | 採用 |
| D-017 | 学生一覧はスキル先頭3件と自己紹介120文字の抜粋を返す。 | カードを比較しやすい情報量に抑え、全文表示を詳細と分離するため。 | 採用 |
| D-018 | 架空学生25人をseedし、一覧の2ページ分をデモできるようにする。 | 登録操作に依存せず、表示とページネーションを確認できるようにするため。 | 採用 |
| D-019 | 学生詳細のメッセージ送信導線はメッセージ機能の実装まで準備中表示で無効化する。 | 未実装画面への遷移や送信可能という誤解を防ぎつつ、次の操作位置を明示するため。 | 採用 |
| D-020 | 企業と学生の組み合わせにつき会話を1件に固定する。 | 同じ相手との履歴を一か所へ集約し、受信一覧の重複を防ぐため。 | 採用 |
| D-021 | 初回送信時に会話とメッセージを同一トランザクションで作成する。 | 本文不正や保存失敗時に空の会話が残ることを防ぐため。 | 採用 |
| D-022 | P0の企業側送信履歴は古い順に全件表示し、ページ分割しない。 | 2週間のMVPでは会話量が限定的で、送受信フローの完成を優先するため。 | 採用 |
| D-023 | メッセージ機能は企業側の送信・履歴と、学生側のログイン・受信確認に分割して実装する。 | 認可と画面状態を実装単位ごとに検証可能にするため。 | 採用 |
