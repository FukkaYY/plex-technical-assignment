# 企業ログイン

## 目的

許可された企業担当者だけが学生情報とメッセージ機能へアクセスできるようにする。

## 優先度・区分

- 優先度: P0
- 設計判断: 企業の公開登録は実装せず、デモ用企業アカウントをseedで用意する。

## 対象ユーザー

seedで登録済みの企業担当者。

## フロー

1. 企業ログイン画面でメールアドレスとパスワードを入力する。
2. Railsが資格情報と `role=company` を検証する。
3. 成功時はセッションを作成し、学生一覧へ遷移する。
4. 失敗時は資格情報のどちらが誤っているかを特定しない共通エラーを表示する。

## API

- `POST /api/v1/session`: ログイン
- `DELETE /api/v1/session`: ログアウト
- `GET /api/v1/me`: 現在のユーザーとロールを取得

## セキュリティ

- RailsセッションとHttpOnly Cookieを使用する。
- Cookieには本番環境で `Secure` と適切な `SameSite` を設定する。
- ログイン失敗時にアカウントの存在を漏らさない。
- 学生ロールで企業画面・企業APIを利用できない。

## 受け入れ条件

- seed企業でログインし、学生一覧へ遷移できる。
- 誤った資格情報ではセッションを作成しない。
- 学生アカウントでは企業向けAPIにアクセスできない。
- ログアウト後は保護されたAPIを利用できない。
