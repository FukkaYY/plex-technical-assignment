# 面談予定の調整

## 目的

既存会話の企業と学生が、サービス内で面談候補を提案・回答し、合意状態を共有できるようにする。

## 優先度・区分

- 優先度: P2
- 設計判断: 企業が提案し、学生が承諾または辞退する単方向の提案フローとする。
- 設計判断: 確定後の書き換えは行わず、再調整時は新しい予定を提案する。

## データ・バリデーション

- 予定は既存の会話に紐づく。
- 開始日時、終了日時、実施方法・場所は必須。補足は任意。
- 実施方法・場所は200文字以内、補足は1,000文字以内。
- 開始日時は作成時点より未来、終了日時は開始日時より後、所要時間は8時間以内とする。
- 画面では日本時間として入力・表示し、DBにはUTCで保存する。
- 状態は `pending`、`accepted`、`declined`、`cancelled` のいずれかとする。

## 状態遷移

- 企業は `pending` の予定だけを `cancelled` にできる。
- 学生は本人宛ての `pending` の予定だけを `accepted` または `declined` にできる。
- `accepted`、`declined`、`cancelled` は終端状態とし、再変更できない。

## API

- `POST /api/v1/students/:student_id/schedule_proposals`: 既存会話へ企業が予定を提案する。
- `PATCH /api/v1/company/schedule_proposals/:id/cancel`: 提案企業が回答待ち予定を取り消す。
- `PATCH /api/v1/schedule_proposals/:id/accept`: 対象学生が予定を承諾する。
- `PATCH /api/v1/schedule_proposals/:id/decline`: 対象学生が予定を辞退する。
- 企業・学生の会話履歴APIへ予定一覧を古い順で含める。
- 他社・他学生の予定は404として存在を隠す。

## 画面

- 企業側会話画面に予定一覧、提案フォーム、回答待ち予定の取消ボタンを表示する。
- 会話がまだない学生には、先にメッセージ送信が必要であることを表示する。
- 学生側会話画面に予定一覧と、回答待ち予定の承諾・辞退ボタンを表示する。
- 両画面で日本時間の日時、実施方法・場所、補足、状態を表示する。

## 対象外

- 外部カレンダー連携、通知、リマインダー、予定重複検出、会議URLの自動発行、確定予定の編集。
