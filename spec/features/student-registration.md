# インターン生登録

## 目的

インターン生本人が認証アカウントとプロフィールを作成し、企業が閲覧できる候補者として登録される。

## 優先度・区分

- 優先度: P0
- 既定: インターン生が登録できる。
- 設計判断: アカウントとプロフィールを1画面・1トランザクションで同時作成する。

## 対象ユーザー

未登録のインターン生。

## 入力項目

| 項目 | 必須 | 制約 |
|---|---:|---|
| 氏名 | 必須 | 100文字以内 |
| メールアドレス | 必須 | 形式確認、大文字小文字を無視して一意 |
| パスワード | 必須 | 8文字以上 |
| パスワード確認 | 必須 | パスワードと一致 |
| 学校名 | 必須 | 200文字以内 |
| 卒業予定年 | 必須 | サーバー上の現在年以上、現在年+10以下の整数 |
| 希望職種 | 必須 | 100文字以内 |
| スキル | 任意 | 1項目50文字以内、最大20件 |
| 自己紹介 | 必須 | 2,000文字以内 |

## フロー

1. トップから学生登録画面へ進む。
2. 必須項目を入力して送信する。
3. Railsがユーザーとプロフィールをトランザクション内で作成する。
4. 成功時はセッションを作成し、学生マイページへ遷移する。
5. 失敗時は項目別エラーを表示し、入力値を保持する。

## API

`POST /api/v1/student_registrations`

- サーバー側で `role=student` を設定し、クライアント指定のroleを信用しない。
- メールアドレスは前後空白を除去し、小文字化して保存する。
- 成功: `201 Created` と `data.user`、`data.student_profile`。`user` は `id`, `email`, `role`、`student_profile` は `id`, `user_id`, `name`, `school_name`, `graduation_year`, `desired_role`, `skills`, `self_introduction` を返す。`password_digest` などの内部情報は返さない。
- 入力不正: `422 Unprocessable Entity`
- メールアドレスの一意性競合も `email` / `taken` のエラーとして `422` を返す。
- ユーザーとプロフィールのどちらかが失敗した場合は両方ロールバックする。

## 入力値の正規化

- パスワード以外の文字列は前後空白を除去する。
- パスワードは入力値を変更せず、確認値との一致を検証する。
- スキルは各項目の前後空白を除去し、空項目と同一表記の重複を除外する。

## 登録後の画面

P0の学生マイページは、登録者名、登録成功状態、ログアウト導線を表示する。受信一覧はメッセージ機能の実装時に追加する。

## データ

- `users`: email, password_digest, role
- `student_profiles`: user_id, name, school_name, graduation_year, desired_role, skills, self_introduction

詳細は `../shared/database.md` を参照する。

## 受け入れ条件

- 正しい入力でユーザーとプロフィールを作成できる。
- 登録直後にログイン状態になる。
- 登録後の学生マイページに登録者名とログアウト導線が表示される。
- 同一メールアドレスを大文字小文字だけ変えて再登録できない。
- パスワードを平文保存しない。
- APIリクエストから企業権限を取得できない。
- プロフィール作成失敗時にユーザーだけが残らない。
